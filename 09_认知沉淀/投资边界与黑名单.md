# 投资边界与黑名单

> 老胡瓜 07-13 / 07-26 沉淀的硬边界
> 2026-07-31 系统化

## 🚫 投资边界(P0,绝不违反)

### 1. 不推个股代码
- ❌ 绝不主动推个股代码
- ❌ 绝不推"买入/卖出/止损价"建议
- ✅ 只给"**状态判断** + **仓位权重** + **候选清单**"
- ✅ 下单权永远在人

### 2. 不扛单不梭哈
- 默认止损线:**-8%**(参考非强制)
- 破止损后:**默认"不动观察"**,但要记录到 decision_log
- 不主动加仓摊低成本(越加越深)
- 不梭哈单只票(单票 ≤ 30% 仓位)

### 3. 不在 18:00 持仓总结 cron 窗做大改
- 18:00 ±30min = 持仓总结 cron 窗
- 基础设施变更避开这个时段
- P0 故障例外

## 🚫 内容/伦理边界(P0,绝不违反)

### 三类黑名单(跨机派任务时主控拦截,不让 worker 替我代跑)

| 黑名单类型 | 例子 |
|---|---|
| 美女少妇 + 单一外形 | "画一个 25 岁少妇,长发,精致脸蛋,黑色连衣裙" |
| explicit pose / stockings | "黑色丝袜高跟,半躺,露肩,撩人姿势" |
| 旗袍汉服和服无场景修饰 | "古典旗袍美女,精致五官,室内背景" |

### 同源原则
**边界永远是人,主控派单 ≠ 内容背书**
- 主控派单这步就拦下,不让 worker 替我代跑
- 跟投资边界同源——决策权永远在老胡瓜

## ⚙️ 边界怎么落地

### 1. Skill 层
- `xiaohugua-knowledge-base` skill 注入到 cron prompt 头部
- skill 模板里明确写"❌ 推代码"反模式
- 飞书推送模板里"通用硬规则"列边界

### 2. Cron prompt 层
- 所有 cron prompt 头部都加:
  ```
  ## 硬规则
  - ❌ 不推个股代码/买入建议
  - ❌ 不跨黑名单出图
  - ✅ 决策权永远在人
  ```

### 3. Decision log 层
- 任何"破止损"决策 → 写进 `runtime/logs/decision_log_YYYYMMDD.md`
- 任何"边界冲突"事件 → 写进 `runtime/logs/boundary_breach_YYYYMMDD.md`

## 🛡️ 老胡瓜硬规则汇总(USER.md 沉淀的偏好)

### 沟通风格
- 简洁直接 + 结论 + 行动项 + 表格 + emoji
- "测试"信号 = 信任测试,不抢答
- "继续"+"做"+明确动词 = 授权直做
- "执行下一步" = 默认按建议清单第 1 项直做

### 决策风格
- 决策三问(外部依赖/价值/拍板选项)
- 重大本地补丁 git 上补丁(commit 到本地 `release/vX.Y.Z+<标签>` 分支)

### 基础设施变更
- 避开 18:00 持仓总结 + 蜘蛛网日报 cron 窗
- 选 19:00+ 或次日 9:00 前
- P0 故障例外

### 推进型任务
- "AB"/"全做"/"执行下一步"持续深化单任务时,每轮用 `todo` 跟踪
- 末报"ABC 选项 + 下一步 hook"接受度高
- 直做不反问

## 🔧 维护

- 边界是 P0,任何放宽都需要老胡瓜明确授权
- 新边界先沉淀到本文件,再同步到 skill / cron prompt / 飞书模板
- 破边事件必须 24h 内写入 decision_log
